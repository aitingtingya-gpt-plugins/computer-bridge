# Computer Bridge

Use original files and local commands on an explicitly selected registered computer.
Connect the plugin to your service's `/mcp` endpoint using OAuth. The base package provides the computer-bridge Skill; optional modules provide their own instructions and capabilities after activation.

Select a computer, open an authorized directory, and retain the returned session and context handles. Short command output is returned directly; use the provided stdout_read/stderr_read parameters for complete output. Recover interrupted requests by their original request ID instead of repeating side effects with a new key.

For terminal or web chat, check `chat.channel` when opening Work or Dot and subscribe once to the plugin-level `chat.channel` event (`arguments: {}`) using MCP Events so `/new`, `/connect`, `/disconnect`, and `/delete` notify Dot automatically. You can also resume a short conversation ID such as `t1` directly with `chat.resume` and subscribe to `chat.message` using MCP Events in Work or Dot. New conversations persist Chat or Super Agent mode. Use the anchored multi-message context, reading original history only when needed. Chat replies use chat.reply; Super Agent candidates/assignments use chat.task and actual authorized host execution, with result/question replies saved transactionally. For Super Agent conversations only, optional chat.repository reads the server-bound GitHub/CNB repository without obtaining credentials or granting permissions (Chat conversations do not bind repositories). A conversation already in use cannot be taken over. The ordinary ChatGPT host outside Work/Dot does not support event wake, which is distinct from Bridge Chat mode.
