# 双向聊天

Computer Bridge 的聊天功能让你在电脑终端或服务端网页中，与已有的 Work／Dot 对话连续沟通。它使用 [MCP Events](https://developers.openai.com/plugins/build/mcp-events) 传递新消息，不需要模型挂起一个命令。模型处理消息时仍可调用桥接器的其它工具，使用原有权限。

## 建立对话

网页打开服务地址的 `/chat`，登录后选择电脑并新建对话。安装后新开终端运行 `cs` 或 `closesi`，默认直接使用当前注册电脑的身份，无需再次登录。输入 `/login` 可切换到账户身份，选择该账户获授权的所有电脑；`/logout` 返回本机身份。终端的详细命令见[终端聊天](chat-terminal.md)。

对话 ID 从 `t1` 顺序增加，不重复使用。标题可自由修改，ID 和历史不变。对话固定属于选中的电脑；本机身份和获授权的账户可访问同一台电脑的对话。账户之间共享设备时也共享其对话。网页页头和终端页头都显示当前电脑与对话 ID。

网页右上角点击“获取连接 ID”，弹窗显示当前短 ID、复制按钮和连接步骤。它只提供连接信息，不会建立或替换模型连接。未选择对话时不能获取 ID。

在 Work 或 Dot 中启用 Computer Bridge，将弹窗中的连接指令发送给它，例如：

> 连接 Computer Bridge 对话 t1：先调用 chat.resume，再使用宿主的事件任务订阅返回的 chat.message 事件；取得凭据后即可用 chat.reply 回复；订阅用于接收后续通知。

首次更新服务器后，在插件连接设置刷新工具和事件目录。`chat.resume` 建立模型写入连接，获得凭据后即可保存回复；`subscribed:false` 仅表示通知尚未订阅。事件订阅由宿主的事件任务能力完成，`events/subscribe` 属于 MCP 协议，不是普通工具列表里的 `chat.subscribe`。消息保存与事件订阅互相独立。Work／Dot 可接收事件唤醒；普通 Chat 不提供这项唤醒能力，原有电脑工具保持可用。

## 恢复与占用

终端输入 `/resume`，从会话名称列表选择并打开；网页可输入 `t1` 或从历史列表打开。模型也可以按 ID 恢复，并通过 `chat.history` 分页读取原文。Bridge ID 标识服务器上的沟通记录，不是宿主自己的对话 ID。

同一个 Bridge 对话只能有一个活动模型端。另一模型对话连接它时，会得到“该对话正在被使用”；不会替换原连接或中断原来的工作。每次 `chat.message` 事件的 `data.connection` 都提供当前连接的回复凭据，模型收到事件后直接使用它调用 `chat.reply`，无需再次调用 `chat.resume`。原连接凭据继续可用，刷新订阅不会产生第二个占用。

终端和网页可同时打开和发送消息。关闭它们、切换页面或短暂断网都不会释放模型端。模型明确断开或取消订阅后，其他模型对话才能连接。通知订阅自然到期不释放原模型的写入授权和占用。断开聊天不停止电脑上已有命令，也不删除聊天历史。

## 消息与附件

网页支持文件选择、拖入附件及粘贴图片。终端使用 `/attach 文件路径`。图片可以预览，文本可以分段查看，其它附件保留原文件并可下载。上传和下载使用分块传输，完成后核对大小和 SHA256。

模型回复使用 `chat.reply`；发送电脑文件使用 `chat.attachment` 的 `from_file`，需要该电脑已授权的工作会话。选中的文件会复制到服务器作为聊天附件，随后在回复中使用 `a1` 等附件短号。聊天不会自动上传工作区或科研项目。

用户消息、模型回复及审批决定在服务器保存后即发送成功，并进入同一份历史。界面始终显示“已保存”，另外显示等待接收方上线、等待通知、暂不可达、宿主已接收、通知配置异常及已回复等状态。宿主接收通知不代表模型已读或已执行。

服务器无法接收时可以发送失败；保存回执中断时显示“结果待确认”。终端使用 `/retry`、网页使用“确认发送结果”，始终按原请求键查询，不重复创建消息。本轮不提供发送端离线持久待发箱。

接收方离线时不持续推送，上线后按游标补收。有效模型订阅暂不可达时，按 30 秒、60 秒、120 秒、之后每 5 分钟重试，并遵守限流等待时间；不再按失败次数丢弃通知。无订阅、到期或明确失效时暂停，恢复有效订阅后补投未确认的通知。历史不受这些通知状态影响。

网页与终端使用独立 WebSocket 接收变化通知，再按游标同步新增消息和状态变化。发送消息及附件仍使用 HTTP。网页隐藏时暂停实时连接，重新打开时补齐变化；短暂断网不会丢失已保存的消息，也不影响电脑连接和模型订阅。

首次恢复时读取所需历史。后续事件包含完整原文且已有足够上下文时，可以直接处理；截断、缺少上下文或需要附件时再调用相应读取工具。消息的按需计时区分保存、首次投递、宿主接收和回复保存；“已送达宿主”不能当作模型已开始思考。

## 保存位置

聊天原文和附件保留到明确删除对话；删除会回收对应附件。Node／Docker 的记录存放在 `DATA_DIR` 中的 SQLite，附件分块位于 `DATA_DIR/chat-attachments`。Cloudflare 使用现有 SQLite Durable Object 分块保存，不需要 R2。

普通电脑操作的文件和命令输出仍保留在电脑，只有主动发送的聊天附件进入服务端存储。服务端更新继续使用原持久存储，以保留账号、对话、订阅和附件。

账户聊天权限沿用已有设备授权。密码变更、停用、删除或撤销设备授权后，对应旧账户连接失效；本机模式使用设备注册身份，不受账户密码修改影响。注销电脑或更换注册凭据会使旧本机连接失效。聊天不会改变完全访问或工作区设置。

## 在对话中审批命令

网页的待审批入口和终端 `/approve` 显示当前电脑的待审批命令，可查看命令、工作目录、理由和有效期，然后单次同意、拒绝或取消。关闭列表或详情不作决定。

通过聊天处理的命令若需要本次扩大权限，模型使用 `computer.exec` 的 `approval_channel="chat"`；审批留在网页或终端，不再同时弹出宿主表单。默认 `host` 继续使用原宿主审批。完全访问已开启时直接执行。

决定作用于原操作，重复答复沿用第一个决定。当前选中的对话会收到一次审批决定消息；模型继续等待原操作，不重新执行命令。电脑暂时离线时，已保存的决定会等待恢复连接。
