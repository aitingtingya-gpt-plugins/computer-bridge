# 双向聊天

Computer Bridge 的聊天功能让你在电脑终端或服务端网页中，与已有的 Work／Dot 对话连续沟通。它使用 [MCP Events](https://developers.openai.com/plugins/build/mcp-events) 传递新消息，不需要模型挂起一个命令。模型处理消息时仍可调用桥接器的其它工具，使用原有权限。

## 建立对话

网页打开服务地址的 `/chat`，登录后选择电脑并新建对话。安装后新开终端运行 `cs` 或 `closesi`，首次通过浏览器连接账号，之后自动绑定当前注册电脑。终端的详细命令见[终端聊天](chat-terminal.md)。

对话 ID 从 `t1` 顺序增加，不重复使用。标题可自由修改，ID 和历史不变。对话固定属于创建它的账号和选中的电脑；共享设备的其他账号不会因此看到该对话。网页页头和终端页头都显示当前电脑与对话 ID。

网页右上角点击“获取连接 ID”，弹窗显示当前短 ID、复制按钮和连接步骤。它只提供连接信息，不会建立或替换模型连接。未选择对话时不能获取 ID。

在 Work 或 Dot 中启用 Computer Bridge，将弹窗中的连接指令发送给它，例如：

> 连接 Computer Bridge 对话 t1：先调用 chat.resume，再使用宿主的事件任务订阅返回的 chat.message 事件；订阅成功后用 chat.reply 回复。

首次更新服务器后，在插件连接设置刷新工具和事件目录。`chat.resume` 只准备连接，返回 `subscribed:false` 时仍需订阅。事件订阅由宿主的事件任务能力完成，`events/subscribe` 属于 MCP 协议，不是普通工具列表里的 `chat.subscribe`。订阅成功后才能通过 `chat.reply` 回复。Work／Dot 可接收事件唤醒；普通 Chat 不提供这项唤醒能力，原有电脑工具保持可用。

## 恢复与占用

终端输入 `/resume`，从会话名称列表选择并打开；网页可输入 `t1` 或从历史列表打开。模型也可以按 ID 恢复，并通过 `chat.history` 分页读取原文。Bridge ID 标识服务器上的沟通记录，不是宿主自己的对话 ID。

同一个 Bridge 对话只能有一个活动模型端。另一模型对话连接它时，会得到“该对话正在被使用”；不会替换原连接或中断原来的工作。原模型端继续使用自己取得的连接凭据，刷新订阅不会产生第二个占用。

终端和网页可同时打开和发送消息。关闭它们、切换页面或短暂断网都不会释放模型端。模型明确断开、取消订阅或订阅到期后，其他模型对话才能连接。断开聊天不停止电脑上已有命令，也不删除聊天历史。

## 消息与附件

网页支持文件选择、拖入附件及粘贴图片。终端使用 `/attach 文件路径`。图片可以预览，文本可以分段查看，其它附件保留原文件并可下载。上传和下载使用分块传输，完成后核对大小和 SHA256。

模型回复使用 `chat.reply`；发送电脑文件使用 `chat.attachment` 的 `from_file`，需要该电脑已授权的工作会话。选中的文件会复制到服务器作为聊天附件，随后在回复中使用 `a1` 等附件短号。聊天不会自动上传工作区或科研项目。

消息在服务器保存后才出现在历史中。界面区分“待投递”“已送达宿主”“已回复”和失败状态；宿主确认收到事件不代表模型已经回复。传输重试使用原消息身份，不重复创建相同消息。终端回执中断时可用 `/retry` 确认原结果。

网页与终端使用独立 WebSocket 接收变化通知，再按游标同步新增消息和状态变化。发送消息及附件仍使用 HTTP。网页隐藏时暂停实时连接，重新打开时补齐变化；短暂断网不会丢失已保存的消息，也不影响电脑连接和模型订阅。

首次恢复时读取所需历史。后续事件包含完整原文且已有足够上下文时，可以直接处理；截断、缺少上下文或需要附件时再调用相应读取工具。消息的按需计时区分保存、首次投递、宿主接收和回复保存；“已送达宿主”不能当作模型已开始思考。

## 保存位置

聊天原文和附件保留到明确删除对话；删除会回收对应附件。Node／Docker 的记录存放在 `DATA_DIR` 中的 SQLite，附件分块位于 `DATA_DIR/chat-attachments`。Cloudflare 使用现有 SQLite Durable Object 分块保存，不需要 R2。

普通电脑操作的文件和命令输出仍保留在电脑，只有主动发送的聊天附件进入服务端存储。服务端更新继续使用原持久存储，以保留账号、对话、订阅和附件。

聊天权限沿用已有账号与设备授权。密码变更、停用、删除或撤销设备授权后，旧连接不能继续访问对应内容；聊天不会修改完全访问、工作区或命令审批设置。
