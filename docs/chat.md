# 双向聊天

Computer Bridge 的聊天功能让你在电脑终端或服务端网页中，与已有的 Work／Dot 对话连续沟通。它使用 [MCP Events](https://developers.openai.com/plugins/build/mcp-events) 传递新消息，不需要模型挂起一个命令。模型处理消息时仍可调用桥接器的其它工具，使用原有权限。

## 建立对话

设备、聊天、我的账号及账号管理共用全宽页面和顶部导航。聊天侧栏可以收起，并拖动分隔线调整宽度；输入区上缘可上下拖动。分隔线也支持方向键调整、双击恢复默认大小。尺寸和折叠状态按账号保存在当前浏览器，窄屏通过抽屉选择电脑与对话。

手机点击聊天页左上角的“☰”打开电脑与对话抽屉；选择对话后自动收起，也可点关闭按钮或抽屉外的遮罩。手机横屏继续使用抽屉。输入区尺寸与桌面分别保存，切换对话不会自动弹出键盘；键盘占用空间时输入区随可见高度调整，较低的输入视图会暂时收起顶部导航。宽公式、代码和表格可在消息内横向滑动，原文与复制入口保持可用。

网页打开服务地址的 `/chat`，登录后选择电脑并新建对话。勾选「保持登录（30 天）」可在重开浏览器后继续使用；默认不勾选。网页输入开头的 `/` 可选择 `/connect` 通知 Dot 连接（60 秒后仍未生效时自动弹出提醒引导手动告知 Dot）、`/disconnect` 通知 Dot 暂停当前对话的事件订阅、`/title` 修改标题、`/delete` 确认删除并通知 Dot 清理已有订阅、`/export` 下载完整会话与附件 ZIP，原右上角操作已移入菜单。网页导出直接由浏览器下载 ZIP，保存位置由浏览器管理；TUI 导出保存本机。两端输入框为空时，上键可召回用户消息进行编辑，不会自动发送。安装后新开终端运行 `cs` 或 `closesi`，首次使用时直接进入当前注册电脑的身份，无需登录。输入 `/login` 可切换到账户身份，选择该账户获授权的所有电脑。重新启动 TUI 会恢复已登录的账户；`/logout` 清除本机保存的凭据并返回本机身份。终端的详细命令见[终端聊天](chat-terminal.md)。

对话 ID 从 `t1` 顺序增加，不重复使用。标题可自由修改，ID 和历史不变。对话固定属于选中的电脑；本机身份和获授权的账户可访问同一台电脑的对话。账户之间共享设备时也共享其对话。网页从侧栏选择当前电脑和对话；侧栏收起或使用手机时，点击消息区左上角的悬浮按钮打开。终端底部显示当前电脑、对话名称及连接状态，右侧固定显示“聊天ID：t1”；两端都可通过 `/connect` 和 `/disconnect` 控制或同步模型订阅通知。

在 Work 或 Dot 中启用 Computer Bridge 时，首次打开即可通过常驻工具 `chat.channel` 的提示建立插件级事件订阅 `chat.channel`。建立之后，网页或终端执行 `/new` 新建对话或 `/connect` 时会自动向 Dot 推送连接通知，由 Dot 自行打开已有或新建该对话的 `chat.message` 订阅，多条对话可同时保持连接；执行 `/disconnect` 会向 Dot 推送暂停通知，由 Dot 暂停（`events/unsubscribe`）或按自身资源情况取消（`chat.disconnect`）订阅；执行 `/delete` 会向 Dot 推送删除通知，若 Dot 本地已有该 `chat_id` 的订阅或任务则永久退订删除，若无则忽略。发出 `/new`、`/connect` 或 `/disconnect` 后不会立即弹窗，仅在超过 1 分钟仍未检测到 Dot 生效时自动弹出提醒，引导手动告知 Dot；弹窗期间若生效则自动关闭，`/delete` 删除后仅在状态栏提示通知状态、不弹窗：

> 请前往 Dot 手动处理对话 t1（可在开启插件级 chat.channel 订阅后自动接收通知）。

首次更新服务器后，在插件连接设置刷新工具和事件目录。`chat.resume` 建立模型写入连接，获得凭据后即可保存回复；`subscribed:false` 仅表示通知尚未订阅。事件订阅由宿主的事件任务能力完成，`events/subscribe` 属于 MCP 协议，不是普通工具列表里的 `chat.subscribe`。消息保存与事件订阅完全独立；服务端不在 `/disconnect` 时阻断投递，消息能否送达仅取决于 Dot 侧事件订阅是否处于连接状态。Work／Dot 可接收事件唤醒；普通 Chat 不提供这项唤醒能力，原有电脑工具保持可用。

## 恢复与占用

终端输入 `/resume`，从会话名称列表选择并打开；网页可输入 `t1` 或从历史列表打开。模型也可以按 ID 恢复，并通过 `chat.history` 分页读取原文。Bridge ID 标识服务器上的沟通记录，不是宿主自己的对话 ID。

同一个 Bridge 对话只能有一个活动模型端。另一模型对话连接它时，会得到“该对话正在被使用”；不会替换原连接或中断原来的工作。每次 `chat.message` 事件的 `data.connection` 都提供当前连接的回复凭据，模型收到事件后直接使用它调用 `chat.reply`，无需再次调用 `chat.resume`。原连接凭据继续可用，刷新订阅不会产生第二个占用。

终端和网页可同时打开和发送消息。关闭它们、切换页面或短暂断网都不会释放模型端。模型明确断开或取消订阅后，其他模型对话才能连接。通知订阅自然到期不释放原模型的写入授权和占用。断开聊天不停止电脑上已有命令，也不删除聊天历史。

## 消息与附件

网页支持文件选择、拖入附件及粘贴图片。终端通过 `/read` 查看收到的文本附件、`/download` 下载原文件；`/export` 可将完整会话及附件下载为离线 ZIP。图片可以预览，文本可以分段查看，其它附件保留原文件并可下载。上传和下载使用分块传输，完成后核对大小和 SHA256。

模型回复使用 `chat.reply`；发送电脑文件使用 `chat.attachment` 的 `from_file`，需要该电脑已授权的工作会话。选中的文件会复制到服务器作为聊天附件，随后在回复中使用 `a1` 等附件短号。聊天不会自动上传工作区或科研项目。

回复正文直接支持 Markdown，数学使用 `$…$`、`$$…$$` 等 LaTeX 分隔符。整篇放在代码围栏中表示展示源码，内部标题和公式不会递归排版；只有明确索要源码时才应这样输出。网页、终端及 `/math` 使用一致的数学语义，终端无法可靠表达的图形保留原文与完整查看入口。

用户消息、模型回复及审批决定在服务器保存后即发送成功，并进入同一份历史。界面始终显示“已保存”，另外显示等待接收方上线、等待通知、暂不可达、宿主已接收、通知配置异常及已回复等状态。宿主接收通知不代表模型已读或已执行。

服务器无法接收时可以发送失败；保存回执中断时显示“结果待确认”。终端自动按原请求键确认，网页使用“确认发送结果”，不重复创建消息。本轮不提供发送端离线持久待发箱。

接收方离线时不持续推送，上线后按游标补收。有效模型订阅暂不可达时，按 30 秒、60 秒、120 秒、之后每 5 分钟重试，并遵守限流等待时间；不再按失败次数丢弃通知。无订阅、到期或明确失效时暂停，恢复有效订阅后补投未确认的通知。历史不受这些通知状态影响。

网页和终端在接近已加载历史顶部时自动按每页 50 条提前读取更早消息，持续上翻直到最早记录。加载保持当前阅读位置，实时审批及消息状态通过增量同步对账；切换身份和对话后不接收旧分页结果。

网页电脑选择框右侧与终端底部显示服务端到所选电脑的往返延迟，与设备管理使用相同的检测及颜色规则：低于 200 ms 绿色、200—499 ms 黄色、500 ms 及以上红色；超时、未知及恢复中黄色，离线灰色。网页可见时每 5 秒刷新当前电脑，隐藏后停止。

网页与终端使用独立 WebSocket 接收变化通知，再按游标同步新增消息和状态变化。发送消息及附件仍使用 HTTP。网页隐藏时暂停实时连接，重新打开时补齐变化；短暂断网不会丢失已保存的消息，也不影响电脑连接和模型订阅。

首次恢复时读取所需历史。后续事件包含完整原文且已有足够上下文时，可以直接处理；截断、缺少上下文或需要附件时再调用相应读取工具。消息的按需计时区分保存、首次投递、宿主接收和回复保存；“已送达宿主”不能当作模型已开始思考。

## 保存位置

聊天原文和附件保留到明确删除对话；删除会回收对应附件。Node／Docker 的记录存放在 `DATA_DIR` 中的 SQLite，附件分块位于 `DATA_DIR/chat-attachments`。Cloudflare 使用现有 SQLite Durable Object 分块保存，不需要 R2。

普通电脑操作的文件和命令输出仍保留在电脑，只有主动发送的聊天附件进入服务端存储。服务端更新继续使用原持久存储，以保留账号、对话、订阅和附件。

账户聊天权限沿用已有设备授权。密码变更、停用、删除或撤销设备授权后，对应旧账户连接失效；本机模式使用设备注册身份，不受账户密码修改影响。注销电脑或更换注册凭据会使旧本机连接失效。

## 电脑权限、工作区和审批

网页和终端均可用 `/permissions` 管理所选电脑的完全访问和各工具规则；用 `/workspaces` 添加、修改、移除工作区与外部子工作区。目标电脑不存在的可创建目录须确认后才创建。移除配置会保留实际目录。TUI 本机身份仅能配置本机，账户身份沿用设备授权。

完全访问控制工作区隔离；工具规则独立，分别设为直接允许、使用前确认或禁止调用，作用于该工具的全部操作。例如文件工具的规则同时适用于读取与写入。选择“使用前确认”后，原调用在获批前不会执行；一次批准不会改变该电脑的设置。

模型与用户可约定在哪儿审批。默认使用宿主弹窗；在聊天中审批时，模型传入 `approval_channel="chat"` 和同一电脑下的 `approval_chat_id="t1"`。受限模式的单次沙盒外命令也可使用这两个参数。如果同一命令同时需要工具确认和沙盒外授权，合并成一次审批。

审批卡在网页和终端同步展示，包含电脑、工具或命令、相关参数摘要及有效期，可选择“批准本次”“拒绝”或取消。终端用 Tab 选择操作、Enter 确认，也可点击。卡片到达不抢走输入焦点。首个有效决定作用于原调用，重复答复不会重新执行。已保存但尚未送到电脑的决定会明确显示。完成后可以展开历史卡片查看详情。
