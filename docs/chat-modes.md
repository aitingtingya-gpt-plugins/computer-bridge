# Chat 与 Super Agent

新建会话可选两种模式，模式保存在服务器，创建后不切换。未传 `mode` 的旧客户端和旧会话默认 `chat`。网页新建弹窗、终端 `/new`、MCP `chat.create` 均支持选择；其中 `Chat` 模式不绑定仓库，仅 `Super Agent` 支持可选仓库绑定。创建重试使用同一 `request_key`，改动模式或仓库参数会被拒绝，不会静默改变已创建的会话。

## Chat

延续现有 Work / Dot 的聊天、通知、回复和电脑工具使用方式，不评估任务、不创建 Ticket、不启动 worker。每次通知带固定到当前 `message_id` 的多条上下文，包括原消息 ID、顺序、角色、来源身份、附件引用、回复关联、截断与较早历史标志。它不会把晚于当前事件的消息夹入旧事件。

原始历史完整保存在服务器；`chat.context` 返回有界上下文，`chat.history` 支持分页回读原文。事件历史仅供理解，不能当新请求重放，也不构成重新授权。旧消息没有可信作者信息时标记 unknown，不猜测作者。不同用户共享电脑不等于同一身份。

## Super Agent

Super Agent 使用固定的 DeepSeek 官方源码和原版角色提示词，Bridge 负责适配消息来源、持久存储与模型主动回报。用户在本页交流；任务执行者是模型承担的职责，不为任务另建聊天会话，也不要求 Dot 内部子 Agent ID。

新消息先保留为待归类输入。模型可以立即路由，也可以先用 `chat.reply` 讨论，再按原消息引用提交归类。讨论期间不派发该请求、不启动原版评估超时。任务及后续输入由原版引擎处理。普通 Chat 的历史和上下文链路不参与。

通过 `chat.task` 提交决定与观察：领取与开始、输入送达与读取、进度与轮次结束分别报告。Bridge 信任当前授权模型的回报，再按原版规则推进。插件没有 Dot 生命周期监听器，事件通知成功不表示模型已读或开始执行。模型依据任务、原版角色规则和现有权限决定执行方式，以及是否安排子 Agent；Bridge 电脑工具与宿主工具不设置额外优先级。

任务号和执行批次号由框架返回。使用原请求键重试以取得已有回执；网络断开本身不意味着执行失败。每次写入复核会话、设备及原作者授权。任务结果通过原版回复入口和投递队列返回本会话；报告任务状态不会自动再发一段相同文字。`saved` 只确认消息保存，通知另外跟踪。

独立 `build/super-agent-host.mjs` 只提供可选的 `SuperAgentTaskClient` 与 `createMcpTaskTransport`，用于转交模型明确填写的调用。它没有自行派发、轮询或执行任务的循环，也不加载另一个模型。

同一个 `chat.message` 可靠传输只唤起一个模式入口。Chat 不经过任务入口；Super Agent 不同时按普通 Chat 执行一次。历史补齐或通知重试不重复入队。服务器已处理的斜杠命令带 `command_processed`，宿主读取状态，不重复命令。审批回执带 `approval_id`，不作为新任务。

常用命令：

- `/task-new 内容`：提交新任务请求，等待主 Agent 归类。
- `/tasks`：任务列表。
- `/task k1 [内容]`：查看/选择任务，并可定向追加消息。
- `/cancel k1`：停止后续工作，不撤销已经开始的外部操作。
- `/retry k1`：明确重试已结束或可重试的任务。
- `/pause`、`/task-resume`：暂停和恢复调度。

终端 `/new` 和 `/resume` 保留创建/打开**会话**的原意。网页与服务端还兼容 `/new 内容`、`/resume` 任务命令，但跨端使用推荐上面的无冲突命令。

## 可选仓库（仅 Super Agent）

仅 `Super Agent` 会话支持不绑定仓库或绑定一个 `{provider: github | cnb, url: HTTPS仓库地址}`；`Chat` 会话与仓库无关，服务端拒绝在 `Chat` 模式下绑定或调用 `chat.repository`，界面与事件也不携带仓库字段。Super Agent 不绑定仓库时非代码任务正常工作。绑定本身仅提供上下文。显式调用 `chat.repository` 可只读查询仓库信息、分支、目录和文件，使用官方 GitHub/CNB API、限量分页与UTF-8安全范围读取。默认匿名访问；CNB 即使公共仓库也可能要求认证，私有仓库同样需当前宿主已授权工具，服务器不会从聊天接收或共享全局令牌。该配置不自动登录、克隆、推送、发 PR/MR、访问 CI 或监听平台事件，也不会授予这些动作的权限。CNB 的认证读取还需有授权的真实宿主验收，不能因模拟契约测试通过就视为端到端可用。

## 边界和恢复

模式和仓库仅在创建时设置。会话、任务和电脑边界由服务端构造，不相信客户端自报身份；凭据或设备密钥不会进入公开上下文。主写入连接、任务原作者权限在事务中复核。任务状态随会话删除而清理，但已经运行的外部命令不因此撤销。

模型回执、工具调用结果或网络响应不确定时，先查询原操作再恢复，不能盲目重跑。恢复不会把原操作自动标为失败或再次执行。上下文有界并保留截断提示，持久历史不等于无限塞入模型窗口。
