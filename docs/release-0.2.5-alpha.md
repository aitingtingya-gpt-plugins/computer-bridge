# Computer Bridge 0.2.5-alpha

新增双向聊天：安装后新开终端运行 `cs` 或 `closesi`，或在服务端 `/chat` 页面选择电脑，与已连接的 Work／Dot 对话交流。

- 设备、聊天、我的账号及账号管理统一全宽布局和顶部导航；聊天侧栏可折叠、宽度及输入区高度可拖动，布局偏好按账号保存在浏览器。
- TUI 消息区占满宽度，历史对话由 `/resume` 分页选择；输入 `/` 显示命令与说明，输入和删除均更新补全。
- 消息保存与接收通知独立；用户消息、模型回复和审批决定先保存，接收方恢复后补收。
- 模型写入连接独立于通知订阅；自然到期和回调故障不妨碍保存回复，原对话占用保持。
- 通知暂不可达时低频重试，明确离线时暂停；回执中断使用原请求键确认，不重复创建消息。
- 对话使用 `t1`、`t2` 递增短 ID，标题独立修改；恢复时保留原始消息及附件。
- 同一对话只允许一个活动模型端，其他连接会显示“该对话正在被使用”。网页与终端可同时使用。
- 通过标准 MCP Events 传递新消息，支持签名验证、持久订阅、去重和失败重试；无需挂起命令。普通 Chat 不提供事件唤醒。
- 新增 `chat.list`、`chat.create`、`chat.resume`、`chat.history`、`chat.reply`、`chat.attachment`、`chat.disconnect`。
- 文字、图片与文件附件支持分块传输及 SHA256；聊天记录和主动发送的附件保存在服务端，电脑工具保持原来的数据位置与权限。
- 服务端更新后，需要在宿主刷新插件工具及事件目录。
- “获取连接 ID”显示当前短 ID、复制按钮及连接步骤；获取 ID 本身不会替换活动连接。
- 网页和终端实时同步新消息及投递状态，恢复连接后按游标补齐；不再周期性重读聊天历史。
- 消息保存后立即投递，各对话独立推进；网页不显示耗时入口，终端可按需使用 `/timing` 诊断。
- 终端默认使用本机身份，`/login` 切换到账户授权的所有电脑，`/logout` 返回本机；网页采用账户权限。
- 对话属于电脑，获授权账户共享对话；唤醒事件包含当前连接的回复凭据。
- 网页和 TUI 在消息流中显示审批卡片；`approval_channel="chat"` 与 `approval_chat_id` 将本次审批发送到同一电脑下的指定对话。完整卡片与决定保留在历史中。
- 聊天按变化更新消息，合并同步和布局刷新；终端选择历史对话不再等待全部分页加载。
- Mac／Windows 安装器自动配置短命令；终端输入 `/resume`，按会话名称选择历史对话。

使用步骤见[双向聊天](chat.md)及[终端聊天](chat-terminal.md)。安装包包含服务端、Windows、Mac 三部分，部署地址由使用者自行填写。
